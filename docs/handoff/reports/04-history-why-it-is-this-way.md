## 2. PARKED regex / "known quirk, kept for parity"
- Mechanism: src/Gate.ts costLevel: `if (g.laterTurns.some((t) => PARKED.test(t))) return 1`, where laterTurns = s.turns.slice(item.turn+1) for that item (Bridge.ts decide). Any parking phrase in any later turn drops cost to level 1, below T_COST_LEVEL=2, so worth_it fails. It is per-item laterTurns but not tied to which resource was parked.
- Origin: PARKED_PATTERNS first appears in b0ffc67 (19 Oct, "Rework speak gate in code", PR #3), copied to TS in 5e5e64c. Gate docstring (src/Gate.ts:10-17, DIRECT): "`silence_cost` was 12% and sat near 0.4 on every snippet. Cost is now derived from the check that disagreed, and drops when the call parked the topic." NextSteps.md in b0ffc67 (now deleted, `git show b0ffc67 -- NextSteps.md`): "`silence_cost` from the check that disagreed (and dropped when the call parks the topic)". So parking exists as a design intent (DIRECT) for the 'topic parked' case; the "any open claim" over-breadth is not described as intended anywhere other than being called a quirk.
- Which parity: (a) test/Gate.parity.test.ts holds src/Gate.ts to spike/egghead_gate.py (frozen Python, `PARKED_PATTERNS` at line 48-53, same `any(...)` over later_turns at line ~91). Fixture: test/fixtures/gate-parity.json, a 20k-point grid from spike/export_gate_parity.py plus the 16 pass-2 snippets that must reproduce spike/REPORT-gate.md (precision/recall 100%/100%, TP 8 FP 0 FN 0 n 16). AGENTS.md "Parity" section: "Changing gate thresholds, wording or Bridge behaviour on purpose means regenerating the fixture and saying so", with commands `python3 spike/gate_eval.py` (must still print REPORT-gate.md's numbers) then `python3 spike/export_gate_parity.py` (writes test/fixtures/gate-parity.json). (b) Also ten full Bridge traces replayed in test/Parity.test.ts. 
- README.md:77 (DIRECT that it is a known quirk): "Known quirk, kept for parity: "park that" anywhere after a claim lowers the cost of every open claim." Added in 351cc3a (README creation); no commit/PR gives more detail (UNKNOWN who identified it or why it was kept rather than fixed).
- What changing it requires (Supported, from AGENTS.md + REPORT-gate.md): change both the TS gate and (if you want parity kept) the Python oracle, or regenerate gate-parity.json via the two commands above and state the intentional change; check the 16-snippet report still matches REPORT-gate.md (caveat in REPORT-gate.md: "rules were written after reading those 16 snippets ... a fit, not a held-out result", so no held-out evidence protects the PARKED behaviour either way). ## 4. partial() barge-in on any open ledger item, skips cooldown
- Code: src/Bridge.ts partial(): `L.open(s.ledger).find((i) => named.has(i.resource))`; L.open = `ledger.filter(i => !i.raised)` (src/Ledger.ts:32), i.e. includes items whose `agent` state is still checking/confirmed/not yet asked. It never calls G.decide, so cooldown, min_silence, floor and worth_it are bypassed; it only requires act >= T_DIRECTIVE (0.3). It does set lastSpokeS (so it starts a cooldown for later flags).
- Rationale recorded: DIRECT but brief, 8976c97 message: "barge-in"; Bridge.ts header comment: "barges in from live partial transcripts (`partial`) when someone is about to act on a claim it knows is wrong." Event note text in code: "Interrupting is cheaper than waiting." AGENTS.md: barge-in fires when "a resource with an open wrong claim (code) plus Decider's 'telling someone to act now'".
- Whether "any open item, even unconfirmed" and "skip cooldown" are deliberate: UNKNOWN. No commit, PR, README or AGENTS text discusses either choice. "Claim it knows is wrong" in the header could be read as relying on the fast check (contradicted) being enough. Test test/Conversation.test.ts:132-140 covers mention vs instruction but I did not see a test for an unconfirmed item (Inferred from my reading of lines 132-140 only; the synthesizer should confirm). The Investigator second look is described as gating the *gate* ("the gate only considers it once confirmed", AGENTS.md); barge-in is not mentioned as subject to it.

## 7. Investigator "second look" and statuses
- Second look why: DIRECT in commit 8976c97 / PR #8 body: "A contradicted claim that survives one turn uncorrected gets a second look before Egg Head interrupts; a claim the call corrects first costs no model call." Src/Bridge.ts header lines 9-11 repeat it; src/Investigator.ts header: "confirm a claim the fast check contradicted, before Egg Head interrupts anyone with it" and "the expensive path Egg Head takes only when Decider and the gate say it is worth it"; README.md:30 and AGENTS.md "Second look, then speak at a gap". Cost motivation echoes the project premise (README/AGENTS: "Bedrock only when it must speak or escalate"). No incident/bug evidence for it (nothing like a false-positive episode was recorded); it appears to be a design addition for the hackathon demo with a coding agent (Supported: the demo script in data/calls and RECORDING.md exercise it; PR #9 body: "1 corrected by the call, 1 cut in, and 1 agent check -> gate -> raised"). The "one turn" interval comes from the existing gate `persisted` rule (laterTurns.length>0) and exp 7 persistence results (FINDINGS line 74), though no doc links them (Inferred).
- Statuses healthy|degraded|down|changed|unchanged: the set is `Status` in src/Checks.ts:26, shared by checks and the Investigator Finding (src/Investigator.ts:21 `status: Status`). Agent CLI demo/agent/bin/egghead:5,10 lists exactly those five; prompt demo/Agent.ts:~70 repeats them. Why no 'unknown': UNKNOWN - no text addresses it. Observations (not intent): Investigator.direct returns the item's own status when the check returns none (`onNone: () => ({status: item.status ...})`), so the type has no way to say "could not determine"; a failure is represented as SupportError (Investigator.confirm returns Effect<Finding, SupportError>) and the Bridge falls back to the direct check on agent failure/timeout (AGENTS.md: "on a timeout the Bridge falls back to the direct check"). So the 'unknown' case is handled as an error path rather than a status (Supported by code + AGENTS.md; not stated as a design reason).
